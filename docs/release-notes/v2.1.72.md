选择性同步二改 v2.3.155，修复客户端 Base URL 路径兼容与 Passkey 失败反馈，更新相关 Go 安全依赖。

## 更新

- 客户端漏写版本路径或重复填写 `/v1` 时，按已注册的同方法网关路由规范化；支持 Codex 无版本段前缀，保留原鉴权、限流、分组与计费链。限制版本段数量，排除管理路由，未知路径的诊断经过既有全局中间件。
- Passkey Redis 会话按流程和用户标记并核对，保留随机 nonce、一次性消费、TTL 和旧 token 兼容。区分 challenge 过期、不匹配、origin 与 RP ID 错误，返回 400，避免刷新登录态并重放一次性请求。
- 资料页补齐 Passkey 加载失败重试、设备取消提示、本地化错误及删除后刷新列表，沿用现有页面和主题。
- 更新 gorilla/websocket、OpenTelemetry API/metric/trace 及必要传递依赖；不导入额外 exporter 或全套多因子迁移。

保留原生厂商路由、真实终态及缓存分桶计费、主管理员 user ID 隔离和现有 TOTP 登录规则。无 SQL 迁移或生产配置变更。

## 验证与范围

本地前端 56 项测试、后端 7 包定向回归的 179 个顶层测试通过；后端含子测试的通过事件为 288，两个口径不能相加。WebSocket 时序用例五轮通过，类型检查、lint、前后端构建与漏洞扫描通过。本地生产构建的 320px 浅色及 1280px 深色浏览器检查共 4 项通过，包括 Passkey 重试、取消及 finish 400 保持登录。发布阶段继续核对 GitHub CI、Release/GHCR 制品身份、备份实际恢复和线上健康。

同步阶段 Redis 使用 miniredis，没有真实设备、实库部署集成或付费上游验证。较大范围服务包命令的旧时序断言修正后仅补跑定向及重复测试，全量验证以发布 CI 实际结果为准。
