# Grok 拒绝收费与会话封禁适配 — 2026-10-21

用户在 v2.2.11 选择性同步后明确要求修正二改实现中的不合理之处并落地完整功能。源版本为 `6c6a9efc96573c879b049265bc57a2d42509bda1`；相关源提交包括 `8d487b465`、`f0d3865f3`、`8262ca158`、`c928b8670`、`80bffc964`、`323793755`、`c0f193e70`、`8b8a190e3`、`6c6a9efc9`。本地按行为适配，保留此前选择性更新。

## 本地修正

- 默认拒绝费为 $0.10/次，分组 `null` 使用默认，显式 `0` 完全免费但仍封禁该会话。固定费不受用户、分组、高峰或模型普通按次价格影响；订阅用户的该项费用明确按余额记账。
- 封禁记录、请求去重、账单效果与冻结的账单恢复任务在同一个数据库事务提交。复用既有 `media_billing_jobs` 和恢复 worker；结算或用量日志写入失败后继续恢复，不再依靠永久 Redis 标记和普通异步任务的偶然先后顺序。
- 同一用户的 Key、分组、模型和文字协议变化不会绕过已匹配的封禁；不同用户隔离。这里明确采用用户级合同，取代此前暂缓记录中的 API-key 隔离预期。
- 无显式会话 ID 时只保存完整被拒历史的指纹，不保存公共问候或末轮问题之前的共享前缀。查询分批遍历全部历史前缀，避免超过 256 条后漏掉保留的拒绝历史。
- 对等的普通文字历史在 Chat Completions、Responses 和 Anthropic Messages 中规范化为相同身份；未知或复杂内容保留结构。缓存提示和每轮变化的响应 ID 不作为永久会话身份。
- IP、账号权限及非 Grok 错误不作为该项内容拒绝收费。匹配后的请求在选号、余额预授权之前本地返回 403，不再访问上游或记第二笔拒绝费用。数据库查询错误停止请求。
- 补齐分组价格的 Ent、仓储、DTO、管理 API、认证缓存及创建/编辑表单投影。新增迁移，保留已应用的 255–266 迁移原始字节。
- 用户平台日、周、月额度的拒绝费在上述事务中写入独立的 JSONB 分量；普通 Redis 绝对快照回刷不会覆盖或重复累计它。准入和 API 展示合并两部分，管理员重置同时清除两部分。金额比较保留普通额度原有精度，月额度返回实际解除限制的时间。
- 账单恢复完成前重放速率缓存和认证缓存失效，持久任务只保存认证缓存的 SHA-256 标识，不保存凭证。简易模式仅处理零费用拒绝任务，不接管已有收费媒体任务。

## 识别和并发边界

已经独立通过准入、正在访问上游的并发请求仍可能各自到达提供方。短事务对已匹配会话只生成一次本地拒绝收费，不能据此宣称所有在途请求只产生一次上游调用。

无稳定会话 ID 时，裁剪或改写旧历史后不能可靠证明其仍为原会话。完整历史完全相同的两个会话也无法仅凭内容区分。宁可保留这些明确边界，也不通过公共前缀猜测而永久误封普通新会话。
