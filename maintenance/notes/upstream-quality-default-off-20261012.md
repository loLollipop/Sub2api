## 默认关闭与凭证边界

- 上游新建、编辑初值、重置表单和 API 省略开关时本来就默认关闭；数据库的布尔字段默认值也为 false。分组检测开关只控制聚合与可见性，不是账号计划的外发总闸。
- 旧存储行的 provider 为 `pelican`、空值或未知值时，读取、表单编辑和运行分流均降级为质量关闭。不会把旧鹈鹕开关当作同意向掺水服务发送密钥。
- 掺水入口必须同时满足计划启用、质量检测开启及明确 `chanshui` provider；每次 POST 和 GET 前重读当前计划。关闭、删除、修改账号、策略或计划版本，以及读取失败，均阻止使用旧计划快照的该次外部请求。重新读取编辑后的已开启计划仍可能按上游设计轮询之前已接受的任务；旧策略结果不能按新策略停用或恢复账号。
- 默认关闭只约束本质量检测功能，不代表其他正常上游 API 请求不发送凭证。手动开启后按上游合约，完整上游 API key、上游地址及模型会发送至所配置的检测服务；界面明确提示只使用可信服务。
- 已被检测服务接受的请求无法撤回。发送前重读降低关闭竞态，不承诺取消所有已经在途的 HTTP 请求。
- 不修改既有迁移，不批量改账号、余额、计费或分组配置。v2.1.10 透传切号修复和其他本地定制保持不变。

## 旧鹈鹕暂停：显式管理员恢复

上游移除了鹈鹕通过后的自动恢复路径。若升级前账号曾被旧检测持久暂停，关闭新检测不会自动恢复账号；本次不新增自动状态机，也不擅自恢复人工停用的账号。

管理员只在以下条件全部核实后恢复单个账号：账号属于当前管理员、未删除、状态 active；原因确实以字面前缀 `scheduled_quality_check:` 开头且无临时禁用截止时间；没有 `extra.chanshui_quality_pauses` 所有权；账号未触发到期自动停用；不存在其他需要保持的限流、封禁或人工停用意图。

恢复须安排维护窗口，先暂停相关计划、账号业务流量及其他状态写入，等在途任务结束，备份并重新核对原因。随后使用已有管理员操作：

1. `DELETE /api/v1/admin/accounts/:id/temp-unschedulable` 清除旧临时不可调度标记与缓存。
2. `POST /api/v1/admin/accounts/:id/schedulable`，请求体 `{"schedulable":true}`，显式恢复持久调度开关。
3. 重读该账号状态并检查临时禁用缓存和服务日志，确认标记已清除、调度已启用、缓存清理没有失败，再恢复流量。仅 HTTP 成功不作为全部状态已恢复的证明。

这些现有操作不是原子 compare-and-clear；清除临时不可调度还会清除模型限流，必须满足没有其他应保留限流的前提。无法隔离并发写入时不要执行，更不能用“关闭分组检测”的快照清理来代替。没有符合条件的旧暂停时不做任何数据写入。上一轮上线前只读检查没有旧计划或旧暂停，此记录不把当时零数据视为通用升级保证。
