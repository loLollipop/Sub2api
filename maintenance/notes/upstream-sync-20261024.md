## 精选适配

### Gemini 原生协议

适配 `7d83b16e7`：Gemini 原生入站在 adaptive 或未显式指定协议时保持原生上游，避免请求中的 googleSearch、签名思考、cachedContent 以及响应 grounding 等原生字段被 OpenAI 转换丢失。显式 chat_completions、responses、anthropic 兼容模式继续原有桥接；普通 OpenAI/Anthropic 入站对 adaptive 的现有判断不变。

本地模型目录已经重构，修复接入账号选择器，保留分组投影、模型授权、模型别名及其他平台边界。原生 adaptive/空协议账号不再计入兼容桥接的合成目录；模型别名从真实上游读取并投影元数据，保留实际 403/404，不补出上游不存在的模型。原生转发记录实际 `/v1beta/models` 端点。API Key 的 Gemini 专用 base URL 优先于通用地址；在账号地址读取时只剥离一次已知协议尾缀，生成、目录及账号测试均复用规范化后的地址，保留 relay/deployment 前缀及现有 URL/路径护栏。修正源提交 getter/builder 重复剥离的问题，例如 `/relay/v1/v1beta` 中的 `/relay/v1` 是部署前缀，不能二次删除。

注意：历史上空协议加自定义地址会按启发式进入 OpenAI 桥接；现在原生 Gemini 入站遵循原生协议。只有 OpenAI 接口的中转应显式设置 chat_completions 或 responses。

### 双重验证输入与弹窗

适配正式版本中的统一 TotpCodeInput：六格展示、单一可聚焦真实输入，支持前导零、全角数字、粘贴分隔符、自动填充、外部重置；拒绝七位等超长粘贴，不静默截取前六位。complete 仅由真实编辑触发，保留值和程序赋值不自动提交。

登录/二次验证在发送请求前同步锁定，防止重复验证；失败清空输入、恢复焦点和重试。启用/关闭 2FA 仍需点击确认，启用保留原密码/邮箱身份验证，关闭必须当前认证器动态码；不引入一次性服务器审批。

二次验证复用本地 BaseDialog，打开时高于当前父窗口，统一 Escape/Tab、body 滚动锁和焦点恢复；后台父窗口移出可访问性对话框范围，保留现有显式 z-index 规则。关闭后重新打开的验证窗口忽略旧请求响应。未用上游全局 useDialogStack 覆盖本地更完整的焦点管理。
