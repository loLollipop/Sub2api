## 本轮采用

1. **Redis 连接池**：采用 FIFO 轮转、最大空闲连接、独立池等待超时、空闲/存活时间回收和 10% 存活时间抖动。默认 pool/min/max idle 为 512/8/64，每次池等待上限 1 秒（库重试可再次等待），空闲/存活时间为 300/1800 秒；显式配置继续优先，最大空闲数按既有最小空闲数和池大小规整。0 可关闭空闲上限或时间回收，手工构造旧配置的池等待 0 保留库默认。独立 reasoning 连接池继续受调用方 deadline 限制且不预热，其空闲上限按自身的最小空闲数 0 规整。没有引入新的池统计后台任务，也没有改部署模板中的既有显式池大小或服务器配置。
2. **异步计费内存和请求隔离**：入队前复制计费所需的请求 ID/调度快照元数据，闭包不再保留 parent request context；公开模型/映射字段在请求仍有效时拍成独立值，避免 Gin 上下文复用后串号。对结果中的 string、*string、[]string 和 OpenAI 请求视图的五个短字符串做复制。覆盖 Messages、Responses、Chat、Embeddings、Gemini、Images、音频、SystemOne、DeepSeek 工具及本地部分用量路径；Alpha Search 的定价时间也提前取值。保留本地有界队列的强制同步兜底、在途余额引用和预授权所有权。Gin 池中的请求体、完整 BodyTop/PrereadBody 生命周期释放属于另一组改动，本轮没有将其一并导入，也不宣称请求内存归零或采用上游压测数字。
3. **监控溢出显示**：直方图 `2147483647` 的 +Inf 桶不再按真实毫秒显示。溢出分位值以最后有限桶 600 秒为下界，必要时用聚合均值近似；它仍是分桶估计，不是真实尾部分位。前端同时拦截负数、非有限值和历史 sentinel。
4. **Ops WebSocket 与身份流程跳转**：校验 Origin 的 HTTP(S) 格式和 Host 语法，比对请求自身 Host，停止读取 X-Forwarded-Host；拒绝全网段代理信任并规范 IPv4-mapped CIDR。保留原有按主机名比较的端口策略和缺失 Origin 的可配置策略。前端登录、OAuth 发起和回调共用站内跳转校验，兼容重复 query 数组，拒绝反斜杠和控制字符；共用的后端 OAuth 跳转校验同样收紧。没有将这一切片描述为整个上游安全提交已全部采用。

错误凭据先返回错误、再对正确密码检查 TOTP 的行为本地已覆盖；不恢复源版 fake challenge，也不放宽本地登录第二因素。
